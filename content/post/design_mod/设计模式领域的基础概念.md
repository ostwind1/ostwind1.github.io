# 面向对象基础概念
面向对象四大基础特性：封装、抽象、继承、多态

## 封装
> 通过访问权限控制保护（隐藏）数据，暴露有限的接口提高类的易用性

Go中通过首字母大小写控制访问权限，小写为包内私有。

❌ 反例：字段直接对外暴露，外部可随意篡改内部状态
```go
package main

import "fmt"

type User struct {
	ID   int
	Age  int // 对外可直接修改，无校验
	Name string
}

func main() {
	u := User{ID: 1, Age: -5, Name: "test"}
	fmt.Println(u.Age)
}
```
✅ 封装：私有字段，通过方法访问、修改，增加校验逻辑
```go
package main

import "fmt"

type User struct {
	id   int
	age  int
	name string
}

func (u *User) SetAge(age int) {
	if age < 0 || age > 120 {
		return
	}
	u.age = age
}
func (u *User) GetAge() int {
	return u.age
}

func main() {
	u := &User{}
	u.SetAge(20)
	fmt.Println(u.GetAge())
}
```

## 抽象
> 隐藏方法具体的实现细节减少调用者心智负担

调用方只关心接口契约，不用关心内部是mysql/redis或者其他实现。
```go
package main

import "fmt"

type UserRepo interface {
	Save(name string) error
}

// Mysql实现
type MysqlUserRepo struct{}
func (m *MysqlUserRepo) Save(name string) error {
	fmt.Printf("mysql save user: %s\n", name)
	return nil
}

func CreateUser(repo UserRepo, name string) error {
	// 调用方不需要知道底层是mysql还是其他存储
	return repo.Save(name)
}
```

## 继承
> 代码复用；表达关联类之间的包含关系

Go没有class继承，使用**结构体嵌套**来模拟继承复用能力。
```go
package main

import "fmt"

type BaseModel struct {
	ID int
}
func (b *BaseModel) GetID() int {
	return b.ID
}

// User 嵌套BaseModel，复用GetID
type User struct {
	BaseModel
	Name string
}

func main() {
	u := User{BaseModel: BaseModel{ID: 100}, Name: "zhangsan"}
	fmt.Println(u.GetID())
}
```

## 多态
> 提高代码的可拓展性和复用性，一个函数可以接收不同实现作为参数

依托Go接口实现多态，同一个函数接收不同接口实现。
```go
package main

import "fmt"

type Animal interface {
	Say()
}

type Dog struct{}
func (d *Dog) Say() {
	fmt.Println("wangwang")
}

type Cat struct{}
func (c *Cat) Say() {
	fmt.Println("miaomiao")
}

// 同一个函数，支持任意Animal实现
func MakeSound(a Animal) {
	a.Say()
}

func main() {
	MakeSound(&Dog{})
	MakeSound(&Cat{})
}
```

## 基于接口（抽象）而非实现编程
要点：
1. 函数的命名不暴露实现细节
2. 封装具体的实现细节
3. 为实现类定义接口，使用者依赖接口而不是实现类来编程

> 不要为每个类都定义接口，仅对于可能会产生变化的不稳定实现定义接口

❌ 面向实现：直接依赖具体结构体
```go
package main

type MysqlOrderRepo struct{}
func (m *MysqlOrderRepo) Save() {}

type OrderService struct {
	repo *MysqlOrderRepo
}
```
✅ 面向抽象：依赖接口
```go
package main

type OrderRepo interface {
	Save()
}
type MysqlOrderRepo struct{}
func (m *MysqlOrderRepo) Save() {}

type OrderService struct {
	repo OrderRepo
}
func NewOrderService(r OrderRepo) *OrderService {
	return &OrderService{repo: r}
}
```

## 贫血模型的传统开发方式
> 数据结构单独定义到一个结构体（BO/PO），用另一个Service类来操作这个数据模型

特点：数据和行为分离，偏向面向过程。
```go
package main

// BO：只存数据，无业务逻辑（贫血）
type OrderBO struct {
	ID     int
	Amount float64
	Status string
}

// Service 承载所有业务逻辑
type OrderService struct{}
func (s *OrderService) Pay(order *OrderBO) {
	order.Status = "paid"
}
```
### 贫血模型的问题
数据和操作相分离，破坏了面向对象的封装性，是一种典型的面向过程风格。

## 充血模型和DDD
> 充血模型：数据和对应的业务逻辑都被封装到同一个结构体中。
> DDD：领域驱动设计，用来指导如何解耦业务系统，划分业务模块。

DDD模式：重Domain、轻Service，Domain内包含业务操作逻辑；开发围绕领域模型而非简单数据模型，领域模型作为可复用业务中间层。

✅ 充血模型示例
```go
package main

import "fmt"

// Order 领域对象：数据 + 自身业务行为
type Order struct {
	id     int
	amount float64
	status string
}

func (o *Order) Pay() {
	if o.status != "unpaid" {
		fmt.Println("订单状态不允许支付")
		return
	}
	o.status = "paid"
}
func (o *Order) Cancel() {
	if o.status == "paid" {
		fmt.Println("已支付订单不可取消")
		return
	}
	o.status = "cancelled"
}
```

## 面向对象设计过程
### 1. 类（结构体）的定义
按照单一职责原则，拆解罗列出功能点；
判断哪些功能点职责相近、操作同一批属性，划分到同一个结构体。

### 2. 类中属性和方法的定义
- 方法：功能点中的**动词**作为候选方法
- 属性：功能点中的**名词**作为候选属性
> 不属于这个结构体的属性和方法，不要放入

### 3. 定义类之间的交互关系｜UML关系
- **泛化**：继承（Go用结构体嵌套模拟）
- **实现**：接口和它的实现结构体
- **聚合**：A包含B，A、B生命周期互相独立
- **组合**：A包含B，B生命周期依赖A；A销毁，B随之销毁
- **关联**：聚合、组合都属于关联
- **依赖**：弱关系，方法参数、返回值使用另外一个类型

简化记忆：日常编码重点关注：**泛化、实现、组合、依赖**；优先用组合替代聚合、普通关联。

### 4. 组装类
把所有领域对象、Repository、Service组装起来，提供统一入口（main）。
```go
package main

func main() {
	// 组装全部依赖，只在入口处初始化
	orderSvc := BuildDependencies()

	if err := orderSvc.PayOrder(1001); err != nil {
		fmt.Println("pay err:", err)
	}
	if err := orderSvc.CancelOrder(1002); err != nil {
		fmt.Println("cancel err:", err)
	}
}
```
