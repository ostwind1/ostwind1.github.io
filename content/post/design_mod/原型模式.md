# 原型模式的原理和应用

## 原型模式的定义

如果对象的创建成本比较大，而同一个类的不同对象之间差别不大，在这种情况下可以利用对已有对象（原型）进行复制的方式来创建新对象，以达到减少对象创建成本的目的。

## 什么样的对象创建成本大？

当对象中的数据需要经过复杂计算，或者需要从 RPC、网络、数据库等慢速 IO 中获取时，这种情况下通过复制已有对象来创建新对象，可能更加省时。

## Golang 例子

假设数据库中有 10 万条搜索关键词，每条关键词包含关键词名称、搜索次数和更新时间。

系统启动时，会从数据库加载全部数据，并构建一个 Map，方便快速查询。

现在有一个问题：数据库中的关键词会定期更新，系统需要每隔一段时间同步数据。

我们可以先复制当前的 Map，然后从数据库中查询新增或者更新的关键词，只更新这些发生变化的数据。这样就不需要每次都重新构建整个 Map。

```go
type SearchWord struct {
    Keyword        string
    Count          int
    LastUpdateTime int64
}

type SearchService struct {
    currentKeywords map[string]*SearchWord
    lastUpdateTime  int64
}

func (s *SearchService) Refresh() {
    // 浅拷贝已有 Map
    newKeywords := make(map[string]*SearchWord, len(s.currentKeywords))
    for k, v := range s.currentKeywords {
        newKeywords[k] = v
    }

    // 查询新增或更新的关键词
    words := getSearchWords(s.lastUpdateTime)

    maxUpdateTime := s.lastUpdateTime

    for _, word := range words {
        if word.LastUpdateTime > maxUpdateTime {
            maxUpdateTime = word.LastUpdateTime
        }

        // 更新关键词
        if oldWord, ok := newKeywords[word.Keyword]; ok {
            oldWord.Count = word.Count
            oldWord.LastUpdateTime = word.LastUpdateTime
        } else {
            newKeywords[word.Keyword] = word
        }
    }

    // 更新服务数据
    s.currentKeywords = newKeywords
    s.lastUpdateTime = maxUpdateTime
}
```

## 深拷贝与浅拷贝

上面的代码在拷贝 Map 的时候使用的是浅拷贝的方法。新创建的 Map 中，元素存储的指针仍然指向原来的 SearchWord 对象。

因此，当我们修改已经存在的关键词时，也会影响旧 Map 中对应的对象。这意味着新旧 Map 并没有实现真正的数据隔离。

对于这种情况，可以使用深拷贝的方式解决，在复制 Map 的同时复制 SearchWord 对象。

有以下几种实现思路。

### 在复制 Map 的时候同时复制 SearchWord

```go
newKeywords := make(map[string]*SearchWord, len(s.currentKeywords))
for k, v := range s.currentKeywords {
    wordCopy := *v // 解引用，复制结构体的值
    newKeywords[k] = &wordCopy
}
```

这里通过解引用获取 SearchWord 的值，再赋值给一个新的变量，从而创建一个新的 SearchWord 对象。

需要注意，这里只是结构体值拷贝。如果结构体内部包含 Slice、Map、指针等引用类型，仍然可能共享底层数据，需要进一步复制。

### 借助序列化和反序列化

还可以通过序列化和反序列化的方式实现深拷贝。例如使用 Go 标准库 `encoding/gob`：

```go
func DeepCopy[T any](src T) (T, error) {
    var buf bytes.Buffer

    err := gob.NewEncoder(&buf).Encode(src)
    if err != nil {
        var zero T
        return zero, err
    }

    var dst T
    err = gob.NewDecoder(&buf).Decode(&dst)
    if err != nil {
        var zero T
        return zero, err
    }

    return dst, nil
}
```

这种方式实现简单，但存在一定的限制，例如只能处理符合 gob 编码要求的数据，不能处理循环引用，也会产生额外的序列化和反序列化开销。

### 直接使用新对象替换旧对象

对于已经发生变化的对象，也可以不修改旧对象，而是直接使用新对象替换。

```go
for _, word := range words {
    if word.LastUpdateTime > maxUpdateTime {
        maxUpdateTime = word.LastUpdateTime
    }

    // 使用新对象替换旧对象
    newKeywords[word.Keyword] = word
}
```

这种方式不需要对整个 Map 进行深拷贝，只需要替换发生变化的对象，可以减少不必要的内存分配。

## 更典型的原型模式例子
```
// 定义原型接口
type Prototype interface {
    Clone() Prototype
}
// 具体原型
type ServerConfig struct {
    Name    string
    Address string
    Port    int
    Options map[string]string
}
// 实现原型接口
func (s *ServerConfig) Clone() Prototype {
    options := make(map[string]string, len(s.Options))
    for k, v := range s.Options {
        options[k] = v
    }

    return &ServerConfig{
        Name:    s.Name,
        Address: s.Address,
        Port:    s.Port,
        Options: options,
    }
}


// 创建原型对象
prototype := &ServerConfig{
    Name:    "Production",
    Address: "127.0.0.1",
    Port:    8080,
    Options: map[string]string{
        "protocol": "http",
        "timeout":  "30s",
    },
}

// 通过原型复制新对象
devConfig := prototype.Clone().(*ServerConfig)

// 修改新对象
devConfig.Name = "Development"
devConfig.Port = 8081
devConfig.Options["protocol"] = "https"
```
