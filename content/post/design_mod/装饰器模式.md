# 什么是装饰器模式

在不修改原有对象代码的情况下，通过创建装饰器对象，动态地为原始对象添加额外功能。装饰器与原始对象实现相同的接口，因此可以在不改变原有调用方式的前提下，组合多个装饰器，灵活地扩展对象的功能。

## 和代理、桥接模式的区别

- **装饰器模式**：不改变原始对象，通过包装原始对象动态增加功能，主要关注如何扩展原始对象的功能。
- **代理模式**：不直接访问原始对象，而是通过代理对象控制对原始对象的访问，主要关注如何控制访问过程。
- **桥接模式**：将抽象和实现解耦，使它们可以独立变化和组合，主要关注如何拆分两个独立变化的维度。

# 通过 Golang 的 io 包了解装饰器模式

Go 标准库的 `io` 包中有不少体现装饰器模式思想的设计，其中 `bufio.Reader` 是一个比较典型的例子。

先看一下 `io.Reader` 接口的定义：

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
```

它只定义了一个 `Read` 方法，表示从数据源读取数据，并将读取到的数据写入字节切片。至于数据具体来自哪里，以及如何读取，`io.Reader` 并不关心。

例如，`os.File`、`bytes.Buffer` 等类型都实现了 `io.Reader` 接口，因此可以统一通过 `Read` 方法读取数据。

这种接口设计带来了很好的扩展性：我们可以在不修改原始 Reader 实现的情况下，通过包装一个新的 Reader，为其增加额外功能。

例如，Go 标准库提供的 `bufio.NewReader`：

```go
file, _ := os.Open("test.txt")
defer file.Close()

reader := bufio.NewReader(file)
```

这里的 `file` 本身就实现了 `io.Reader` 接口，而 `bufio.NewReader` 接收一个 `io.Reader`，返回一个带缓冲功能的 `*bufio.Reader`。

`bufio.Reader` 同样实现了 `io.Reader` 接口，因此它可以继续传递给其他需要 `io.Reader` 的函数，而调用者不需要关心底层的具体实现。

可以将它们之间的关系理解为：

```text
os.File
   |
   v
bufio.Reader
   |
   v
调用者
```

`bufio.Reader` 内部维护了一个缓冲区。当调用者读取数据时，它会优先从缓冲区中读取；当缓冲区中的数据不足时，再从底层 Reader 中读取数据填充缓冲区。

这样就为原始 Reader 增加了缓冲读取的能力，而不需要修改原始 Reader 的代码，也不需要改变调用者的使用方式。

再看一个简化的装饰器实现：

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}

// 原始对象
type FileReader struct {
    // 文件相关字段
}

func (f *FileReader) Read(p []byte) (int, error) {
    // 从文件读取数据
    return 0, nil
}

// 装饰器
type BufferedReader struct {
    reader Reader
}

func (b *BufferedReader) Read(p []byte) (int, error) {
    // 在这里实现缓冲逻辑
    return b.reader.Read(p)
}
```

`BufferedReader` 持有一个 `Reader` 接口，同时自己也实现了 `Reader` 接口。调用者不需要关心底层究竟是 `FileReader` 还是 `BufferedReader`，只需要通过统一的 `Read` 方法读取数据即可。

实际上，Go 标准库中的 `bufio.Reader` 就是类似的设计，只不过它内部还维护了缓冲区，并实现了完整的缓冲读取逻辑。

**这种设计有什么意义？**

1. **扩展功能而不修改原始对象**：可以通过包装原始 Reader，为其增加缓冲、日志、数据处理等功能，而不需要修改原始 Reader 的代码。
2. **提高代码复用性**：装饰器面向接口编程，可以包装任何实现了 `io.Reader` 的对象，而不需要针对不同的数据源重复实现扩展逻辑。
3. **支持功能组合**：多个装饰器可以层层嵌套，每个装饰器只负责自己的功能，从而灵活组合出不同的读取能力。

Go 标准库的 `io` 包还提供了 `io.TeeReader`、`io.LimitReader` 等工具。它们分别实现了读取数据时同步写入另一个 Writer、限制读取数据量等功能，也体现了通过包装接口扩展能力的设计思想。

通过 `io.Reader` 可以看到，装饰器模式的核心并不复杂：让装饰器和原始对象实现相同的接口，同时让装饰器持有原始对象，通过委托原始对象的调用，在此基础上增加额外功能。
