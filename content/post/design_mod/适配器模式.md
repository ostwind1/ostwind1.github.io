# 适配器模式的原理与实现

适配器模式用于将由于接口不兼容而无法一起工作的类，通过适配器转换为兼容的接口，使调用者无需修改原有代码，就能使用不兼容的接口。

适配器模式有类适配器和对象适配器两种实现方式，主要区别在于适配器与被适配者之间的关系：类适配器使用继承，对象适配器使用组合。

由于 Go 不支持传统的类继承，因此通常使用结构体嵌入模拟类适配器，或者直接使用组合实现对象适配器。

## 类适配器

使用继承关系实现。在 Go 中，可以通过结构体嵌入实现类似的效果。

```go
// 目标接口：调用者期望使用的接口
type Target interface {
    Request1() string
    Request2() string
}

// 被适配者
type Adaptee struct{}

func (a *Adaptee) SpecificRequest1() string {
    return "被适配者的功能1"
}

func (a *Adaptee) Request2() string {
    return "被适配者的功能2"
}

// 类适配器：嵌入 Adaptee，复用其方法
type ClassAdapter struct {
    Adaptee
}

// 实现与被适配者接口不兼容的方法
func (a *ClassAdapter) Request1() string {
    return a.SpecificRequest1()
}

// Request2() 直接复用 Adaptee 提升的方法

func main() {
    var target Target = &ClassAdapter{}
    fmt.Println(target.Request1())
    fmt.Println(target.Request2())
}
```

这里通过结构体嵌入复用了 `Adaptee` 的方法。由于 `Request2()` 与目标接口的方法签名一致，因此可以直接通过方法提升满足 `Target` 接口，无需额外实现。

## 对象适配器

使用组合关系实现，通过持有被适配者对象，将目标接口的方法调用转发给被适配者。

```go
// 目标接口
type Target interface {
    Request1() string
    Request2() string
}

// 被适配者
type Adaptee struct{}

func (a *Adaptee) SpecificRequest1() string {
    return "被适配者的功能1"
}

func (a *Adaptee) Request2() string {
    return "被适配者的功能2"
}

// 对象适配器：组合 Adaptee 对象
type ObjectAdapter struct {
    adaptee *Adaptee
}

// 需要逐个实现目标接口的方法
func (a *ObjectAdapter) Request1() string {
    return a.adaptee.SpecificRequest1()
}

// 将调用转发给 Adaptee
func (a *ObjectAdapter) Request2() string {
    return a.adaptee.Request2()
}

func main() {
    adaptee := &Adaptee{}
    var target Target = &ObjectAdapter{
        adaptee: adaptee,
    }

    fmt.Println(target.Request1())
    fmt.Println(target.Request2())
}
```

这里由于使用组合而不是结构体嵌入，`Adaptee` 的方法不会自动提升到 `ObjectAdapter`，因此需要逐个实现目标接口的方法，并将调用转发给被适配者。

## 适配器模式的使用场景

1. **封装有缺陷的接口设计**：当已有接口设计不合理或不符合当前需求时，可以通过适配器进行封装，避免直接修改原有代码。
2. **统一多个外部类的接口设计**：当需要使用多个外部系统或第三方库，而它们提供的接口不一致时，可以通过适配器统一调用方式。
3. **替换依赖的外部系统**：当需要更换外部依赖时，可以通过适配器将新系统的接口转换为原有接口，降低替换成本。
4. **兼容老版本接口**：当接口升级后，可以通过适配器将新接口转换为旧接口，保证原有调用方继续正常工作。
5. **适配不同格式的数据**：当不同系统之间的数据格式不一致时，可以通过适配器完成数据格式转换。

## 代理、桥接、适配器、装饰器的区别

- **代理模式**：通过代理对象控制对原始对象的访问，例如鉴权、限流、监控等。代理对象与原始对象通常实现相同的接口，重点在于控制访问。
- **桥接模式**：将抽象部分与实现部分分离，使它们可以独立变化，重点在于解决多个维度的变化带来的类爆炸问题。
- **装饰器模式**：在不改变原始对象接口的情况下，通过装饰器对原始对象的功能进行增强，并支持多个装饰器嵌套使用。
- **适配器模式**：将一个已有接口转换为调用者期望的接口，重点在于解决接口不兼容问题，通常是一种事后的兼容策略。
