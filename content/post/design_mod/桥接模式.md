# 桥接模式的定义

> Decouple an abstraction from its implementation so that the two can vary independently。
>
> 将抽象和实现解耦，让它们可以独立变化。

当一个系统中存在多个可以独立变化的维度时，可以将这些维度拆分为独立的类体系，通过组合的方式建立联系，让它们可以独立扩展，而不是通过继承实现不同维度的组合，避免类的数量随着维度组合呈乘法增长。

这种设计方式也符合组合优于继承的设计原则。

# 桥接模式的实例

假设我们要开发一个消息通知系统。

通知有两种分类方式：

+ 通知类型：普通通知、紧急通知。
+ 发送渠道：邮件、短信、微信。

这两个维度可以独立变化，例如新增一种通知类型，不应该影响发送渠道；新增一种发送渠道，也不应该影响通知类型。

如果使用继承的方式来编程，那么每一种组合都需要一个新的类。例如，普通通知和紧急通知分别通过邮件和短信发送，就需要四个具体组合类。

```go
// 将两个变化维度绑定在一个类中
type Notification interface {
    Send()
}

// 普通通知 + 邮件
type NormalEmailNotification struct{}

func (n *NormalEmailNotification) Send() {}

// 普通通知 + 短信
type NormalSMSNotification struct{}

func (n *NormalSMSNotification) Send() {}

// 紧急通知 + 邮件
type UrgentEmailNotification struct{}

func (n *UrgentEmailNotification) Send() {}

// 紧急通知 + 短信
type UrgentSMSNotification struct{}

func (n *UrgentSMSNotification) Send() {}
```

但是如果使用桥接模式，可以将通知类型和发送渠道拆分为两个独立变化的维度，让它们各自独立扩展，再通过组合建立联系。

```go
// 通知类型
type Notification interface {
    Send()
}

// 普通通知类型
type NormalNotification struct {
    sender MessageSender
}

func (n *NormalNotification) Send() {
    n.sender.SendMessage("普通通知")
}

// 紧急通知类型
type UrgentNotification struct {
    sender MessageSender
}

func (n *UrgentNotification) Send() {
    n.sender.SendMessage("紧急通知")
}

// 发送渠道
type MessageSender interface {
    SendMessage(message string)
}

// 邮件发送渠道
type EmailSender struct{}

func (e *EmailSender) SendMessage(message string) {
    fmt.Println("邮件发送:", message)
}

// 短信发送渠道
type SMSSender struct{}

func (s *SMSSender) SendMessage(message string) {
    fmt.Println("短信发送:", message)
}

// 动态组合：普通通知 + 邮件
notification := &NormalNotification{
    sender: &EmailSender{},
}

notification.Send()
```

如果后续增加新的通知类型或者发送渠道，只需要实现对应的类型或者渠道即可，不需要为每一种组合创建新的类，从而避免类的数量随着维度组合呈乘法增长。
