# 模板方法模式的原理和实现

模板方法模式在一个方法中定义一个算法骨架，并将某些步骤延迟到具体实现类中完成。这样可以让具体实现类在不改变算法整体结构的情况下，重新定义算法中的某些步骤。这里的算法可以理解为一系列业务逻辑的执行流程。

```go
// 定义可变步骤
type Method interface {
    Method1()
    Method2()
}

// 具体实现
type ConcreteClass1 struct{}

func (c *ConcreteClass1) Method1() {
    fmt.Println("ConcreteClass1 Method1")
}

func (c *ConcreteClass1) Method2() {
    fmt.Println("ConcreteClass1 Method2")
}

// 模板类
type Template struct {
    method Method
}

// 模板方法：定义固定执行流程
func (t *Template) TemplateMethod() {
    fmt.Println("执行公共逻辑")
    t.method.Method1()
    fmt.Println("执行公共逻辑")
    t.method.Method2()
    fmt.Println("执行公共逻辑")
}

func main() {
    demo := &Template{method: &ConcreteClass1{}}
    demo.TemplateMethod()
}
```

# 模板方法模式的作用

## 复用

模板方法模式将不变的流程抽象到模板方法中，将变化的部分留给具体实现类完成。不同的实现类可以复用模板方法中定义的执行流程。

## 扩展

通过将变化的步骤延迟到具体实现类中完成，可以在不修改模板类代码的前提下，定制算法中的部分步骤。

# 模板方法模式和回调

模板方法模式和回调函数解决的问题相似，都是将固定流程与可变步骤分离，从而实现代码复用和功能扩展。

两者的主要区别在于实现方式：

- 模板方法模式通常通过继承实现，子类重写父类中的部分方法。
- 回调函数通过组合实现，将可变步骤作为函数参数传入，由模板函数在合适的时机调用。

回调函数不依赖继承，组合方式更加灵活。

Go 没有继承机制，通常可以使用函数参数实现类似模板方法模式的效果，也更加符合 Go 的语言风格。

```go
func TemplateMethod(method1, method2 func()) {
    fmt.Println("公共逻辑")
    method1()
    fmt.Println("公共逻辑")
    method2()
    fmt.Println("公共逻辑")
}
```
