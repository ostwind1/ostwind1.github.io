# 观察者模式的原理

观察者模式通过在对象之间建立一对多的依赖关系，当一个对象的状态发生改变时，所有依赖它的对象都会自动收到通知，并执行相应的操作。

其中，被依赖的对象称为被观察者（Subject），依赖它的对象称为观察者（Observer）。

## 同步阻塞观察者模式的实现

```go
// Observer：观察者接口
type Observer interface {
    Update(message string)
}

// Subject：主题，维护观察者列表
type Subject struct {
    observers []Observer
}

// 注册观察者
func (s *Subject) Register(observer Observer) {
    s.observers = append(s.observers, observer)
}

// 移除观察者
func (s *Subject) Remove(observer Observer) {
    for i, o := range s.observers {
        if o == observer {
            s.observers = append(s.observers[:i], s.observers[i+1:]...)
            return
        }
    }
}

// 通知所有观察者
func (s *Subject) Notify(message string) {
    for _, observer := range s.observers {
        observer.Update(message)
    }
}

// 具体观察者：邮件通知
type EmailObserver struct{}

func (e *EmailObserver) Update(message string) {
    fmt.Println("邮件通知：", message)
}

// 具体观察者：短信通知
type SMSObserver struct{}

func (s *SMSObserver) Update(message string) {
    fmt.Println("短信通知：", message)
}

func main() {
    subject := &Subject{}

    // 注册观察者
    subject.Register(&EmailObserver{})
    subject.Register(&SMSObserver{})

    // 状态发生变化，通知所有观察者
    subject.Notify("您有一条新消息")
}
```

这里采用同步阻塞的方式通知观察者。`Notify()` 会依次调用所有观察者的 `Update()` 方法，只有当前观察者执行完成后，才会继续通知下一个观察者。

## 异步非阻塞观察者模式的实现

如果希望观察者之间互不影响，可以通过 Goroutine 实现异步通知。下面实现一个简易的 EventBus（事件总线），通过 Topic 管理订阅关系。

```go
type Handler func(event any)

type EventBus struct {
    mu       sync.RWMutex
    handlers map[string][]Handler
}

func NewEventBus() *EventBus {
    return &EventBus{
        handlers: make(map[string][]Handler),
    }
}

// 注册订阅者
func (bus *EventBus) Subscribe(topic string, handler Handler) {
    bus.mu.Lock()
    defer bus.mu.Unlock()

    bus.handlers[topic] = append(bus.handlers[topic], handler)
}

// 发布事件
func (bus *EventBus) Publish(topic string, event any) {
    bus.mu.RLock()
    handlers := append([]Handler(nil), bus.handlers[topic]...)
    bus.mu.RUnlock()

    for _, handler := range handlers {
        handler(event)
    }
}

// 异步发布事件
func (bus *EventBus) PublishAsync(topic string, event any) {
    bus.mu.RLock()
    handlers := append([]Handler(nil), bus.handlers[topic]...)
    bus.mu.RUnlock()

    for _, handler := range handlers {
        // 通过 Goroutine 异步执行
        go handler(event)
    }
}
```

这里使用 `map[string][]Handler` 维护 Topic 和订阅者之间的关系。发布事件时，根据 Topic 找到对应的 Handler 并执行。

其中，`Publish()` 采用同步方式依次执行 Handler，`PublishAsync()` 则通过 Goroutine 并发执行 Handler，实现异步通知。

另外，通过 `sync.RWMutex` 保证订阅关系的并发安全。发布事件时，会在读锁保护下复制一份 Handler 列表，然后释放锁，再执行回调，避免 Handler 执行期间长期占用锁。

# 观察者模式的使用场景

观察者模式主要解决以下问题：

1. **解耦发布者和订阅者**：发布者只负责发送通知，不需要了解订阅者的具体业务逻辑。
2. **提高拓展性**：新增观察者无需修改发布者的代码，只需要注册新的观察者即可。
3. **实现一对多通知**：一个对象发生变化时，可以同时通知多个依赖它的对象。

常见应用场景：

- 电商系统中，订单状态发生变化后，触发库存更新、物流通知、消息推送等操作。
- 用户注册成功后，触发发送欢迎邮件、发放新人奖励等任务。
- 配置发生变更后，通知多个服务或组件更新配置。
