# 代理模式的原理解析

在不修改原始类代码的情况下，通过引入代理类，为原始类附加额外功能。

如果原始类实现了接口，代理类通常需要实现相同的接口；如果原始类没有定义接口，则可以通过继承原始类的方式实现代理。

```go
// 抽象接口
type UserService interface {
    GetUser(id int) string
}

// 原始对象
type RealUserService struct{}

func (s *RealUserService) GetUser(id int) string {
    fmt.Println("查询数据库...")
    return fmt.Sprintf("User-%d", id)
}

// 代理对象
type UserServiceProxy struct {
    realService UserService
}

func (p *UserServiceProxy) GetUser(id int) string {
    // 前置增强
    fmt.Println("记录请求日志")

    // 调用真实对象
    result := p.realService.GetUser(id)

    // 后置增强
    fmt.Println("记录响应日志")

    return result
}
```

## 动态代理

在 Java 中，可以基于反射机制，在运行时动态生成代理类，不需要事先编写代理类代码，从而减少重复开发工作。

Spring AOP 底层就是基于动态代理实现方法拦截的。

## 代理模式的应用场景

1. **将业务功能与附加功能解耦**，例如：监控、统计、鉴权、限流、事务、幂等、日志等。
2. **RPC 和缓存**
    1. 在 RPC 框架中，通过代理将本地方法调用转换为远程调用。
    2. 在缓存场景中，通过缓存代理为原始数据获取方法增加缓存逻辑，实现旁路缓存。
