# 为什么需要建造者模式

当对象的构造过程非常复杂，比如需要初始化很多属性时，如果将这些参数都放在构造函数中，会导致构造函数参数过多。如果使用先创建对象再调用 Set 方法的方式，又会导致在所有 Set 方法调用结束前，对象处于不完整的状态。

建造者模式将复杂的初始化操作封装起来，把复杂的构建过程拆分成多个步骤，并在最终构建前进行校验，让构建过程更加灵活、易读和易于维护。

```go
type HttpRequest struct {
	URL     string
	Method  string
	Timeout time.Duration
	Headers map[string]string
}

type HttpRequestBuilder struct {
	url     string
	method  string
	timeout time.Duration
	headers map[string]string
}

// 创建 Builder，并设置默认值
func NewHttpRequestBuilder() *HttpRequestBuilder {
	return &HttpRequestBuilder{
		method:  "GET",
		timeout: 3 * time.Second,
		headers: make(map[string]string),
	}
}

func (b *HttpRequestBuilder) URL(url string) *HttpRequestBuilder {
	b.url = url
	return b
}

func (b *HttpRequestBuilder) Method(method string) *HttpRequestBuilder {
	b.method = method
	return b
}

func (b *HttpRequestBuilder) Timeout(timeout time.Duration) *HttpRequestBuilder {
	b.timeout = timeout
	return b
}

func (b *HttpRequestBuilder) Header(key, value string) *HttpRequestBuilder {
	b.headers[key] = value
	return b
}

// 最终构建对象
func (b *HttpRequestBuilder) Build() (*HttpRequest, error) {
	if b.url == "" {
		return nil, errors.New("url cannot be empty")
	}

	return &HttpRequest{
		URL:     b.url,
		Method:  b.method,
		Timeout: b.timeout,
		Headers: b.headers,
	}, nil
}

// 调用建造者模式
request, err := NewHttpRequestBuilder().
	URL("https://example.com").
	Method("POST").
	Timeout(5 * time.Second).
	Header("Content-Type", "application/json").
	Build()
```

# 建造者模式和工厂模式的区别

建造者模式是通过建造者来**创建同一种类型**的对象。

工厂模式是通过工厂类来**创建不同类型**的对象。

> 顾客走进一家餐馆点餐，我们可以利用工厂模式，根据用户不同的选择，来制作不同的食物。
>
> 对于同一种食物，我们可以通过建造者模式，为用户定制不同的配料和口味。
